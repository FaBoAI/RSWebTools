# RobStride QDD コンフィギュレータ (RSWebTools)

RobStride 純正 **USB-CAN アダプタ** 経由で RobStride QDD アクチュエータ (RS00〜RS06) を
ブラウザから設定・動作確認するツールです。

## 2 つの版

| | Web 版 | ローカル版 |
|---|---|---|
| 使い方 | <https://rs.fabo.io> を開くだけ | `./run.sh` で起動 |
| インストール | 不要 | Python 3.10+ |
| 対応ブラウザ | Chrome / Edge (Web Serial API) | 任意 |
| 用途 | 通常の設定作業 | CLI・自動化・実機なしの検証 |

**プロトコル定義は共通です。** 機種プロファイルとパラメータ表は
`backend/models.py` / `backend/params.py` を唯一の情報源とし、Web 版が使う
`webserial/tables.js` はそこから生成しています (CI で同期を検証)。

```bash
python tools/gen_js_tables.py    # backend の定義から webserial/tables.js を再生成
```

## 実装の根拠

プロトコルは各機種の公式ユーザーマニュアルから起こしました。マニュアル記載の実フレーム

```
41 54 90 07 e8 0c 08 05 70 00 00 01 00 00 00 0d 0a
```

をバイト単位で再現する回帰テストを Python 版・Web 版の両方に置いています。
機種ごとに異なる P/V/T/KP/KD のスケーリングレンジも、各マニュアルの
`#define P_MIN` … から採録しています。詳細は [docs/protocol.md](docs/protocol.md)。

実機 (RS00 / RS06) で全機能の動作を確認済みです。

## ローカル版の起動

```bash
./run.sh
```

初回は仮想環境の作成と依存パッケージのインストールが自動で走ります。
起動後 <http://127.0.0.1:8765> を開いてください。

ポートを変えたい場合:

```bash
PORT=9000 ./run.sh
```

テスト:

```bash
./.venv/bin/python -m pytest tests -q
```

## 使い方

| 手順 | 操作 |
|---|---|
| 1 | サイドバーでシリアルポート (CH340) を選び **接続** |
| 2 | **スキャン** でバス上のモータ CAN_ID を検出 |
| 3 | **機種** を実機に合わせて選択 (重要 — 下記参照) |
| 4 | 「パラメータ設定」タブで **全パラメータ読出** → 値を編集 → **書込** |
| 5 | 恒久化する場合は **モータへ保存** (通信タイプ 22) |

### 機種選択が重要な理由

運動制御モードの指令とフィードバックは、物理量を 16bit 整数へ線形スケーリングして
やり取りします。そのレンジ (`P_MIN/P_MAX`, `V_*`, `T_*`, `KP_*`, `KD_*`) は**機種ごとに異なります**。
選択を誤ると角度・速度・トルクの値がすべてずれます。

| 機種 | 位置 [rad] | 速度 [rad/s] | トルク [Nm] | Kp | Kd |
|---|---|---|---|---|---|
| RS00 | ±12.57 | ±33 | ±14 | 0–500 | 0–5 |
| RS01 | ±12.57 | ±44 | ±17 | 0–500 | 0–5 |
| RS02 | ±12.57 | ±44 | ±17 | 0–500 | 0–5 |
| RS03 | ±12.57 | ±20 | ±60 | 0–5000 | 0–100 |
| RS04 | ±12.57 | ±15 | ±120 | 0–5000 | 0–100 |
| RS05 | ±12.57 | ±50 | ±5.5 | 0–500 | 0–5 |
| RS06 | ±12.57 | ±50 | ±36 | 0–5000 | 0–100 |

出典は各機種の公式ユーザーマニュアル (2025-11-12 版) の `#define P_MIN` 以下のサンプルコードです。
値は [`backend/models.py`](backend/models.py) にまとめてあり、firmware 更新等でずれた場合はここを直します。

> 電流指令 (`iq_ref` / `limit_cur`) のレンジは RS00 (±16A) 以外は原典を確認できていないため
> `i_max = None` としてあります。この場合 UI は入力レンジを制限せず、モータから読み出した
> `limit_cur` を目安として表示します。

## 安全機構

動作を伴う操作には多重の歯止めを入れてあります。

- **動作許可 (ARM) トグル** — ヘッダにあるソフトウェアインターロック。OFF の間は
  運転許可・運動制御・指令値書込がサーバ側で `423` として拒否されます。
- **非常停止ボタン** — 既知の全モータへ応答待ちなしで停止フレーム (通信タイプ 4) を送り、
  同時に ARM を解除します。**スペースキー**でも発火します。
- **停止・故障クリアは常時有効** — ARM が OFF でも押せます。
- **確認ダイアログ** — 原点設定・CAN_ID 変更・保存・ボーレート変更・プロトコル変更。
- ARM を OFF に戻したときも保険として停止フレームを送出します。

> トルク制限・保護温度・過温度時間は、公式マニュアルが変更しないよう明記しています。
> UI 上は編集できますが、変更は自己責任で行ってください。

## 機能

### パラメータ設定
公式パラメータ表 (0x7005〜0x702B) を種別ごとにグループ化して表示。個別書込・一括書込・
JSON エクスポート/インポート・不揮発保存に対応。読み出し専用パラメータ (mechPos / iqf /
mechVel / VBUS) は編集不可として区別しています。

### 運転・テスト
`run_mode` の切替と、モードごとに必要な指令パラメータだけを表示します
(マニュアルの制御手順に対応)。

| モード | 表示される指令 |
|---|---|
| 0 運動制御 | 専用パネル (p_set / v_set / t_ff / Kp / Kd) |
| 1 位置 PP | loc_ref, vel_max, acc_set, limit_cur |
| 2 速度 | spd_ref, acc_rad, limit_cur |
| 3 電流 | iq_ref |
| 5 位置 CSP | loc_ref, limit_spd, limit_cur |

運動制御モードは 20Hz の連続送信にも対応します。

### デバイス設定
デバイス ID / MCU 固有 ID / ファームウェアバージョンの取得、機械原点設定、CAN_ID 変更、
CAN ボーレート変更、プロトコル切替。

**インデックス調査**: マニュアル未掲載の 0x20xx / 0x30xx 系インデックスを
**読み出しのみ**で総当たり調査し、float / uint32 の両解釈を並べて表示します。
実機のファームウェアが実際に持つパラメータ表を安全に調べるための機能です。

### CAN コンソール
送受信フレームを時刻・方向・拡張 ID・通信タイプ名・データで一覧表示。
任意の拡張 ID + データを手打ちで送信することもできます。切り分け用に
アダプタへ `AT+AT` を送るボタンも用意しています。

## 実機なしで動作確認する

仮想 RobStride モータを PTY 上に立てられます。実機が無くても UI とバックエンドを
端から端まで動かせるので、開発時の確認や、実機が応答しないときの切り分けに使えます。

```bash
./.venv/bin/python tools/fake_motor.py --ids 1,5 --model RS00
```

表示された `/dev/ttysNNN` を UI のシリアルポート欄に入力し、**シリアル速度は 115200**
を選んで接続してください (PTY は非標準ボーレートを受け付けません)。
スキャン・パラメータ読み書き・運転許可・能動送信によるライブテレメトリ・保存・
CAN_ID 変更まで、実機と同じ手順で動作します。

## トラブルシューティング

### Web 版でモータが見つからない (ローカル版と併用しているとき)

**Web 版とローカル版を同時に接続しないでください。** シリアルポートは排他制御されるため、
先に掴んだ側だけが通信できます。

pyserial は POSIX 環境でポートを排他モードで開くので、ローカル版が接続したままだと
ブラウザ側は通信できません。ローカル版の UI で **切断** するか、サーバーを止めてください。

```bash
lsof /dev/cu.wchusbserial*        # ポートを掴んでいるプロセスを確認
pkill -f "uvicorn backend.server" # ローカル版サーバーを停止
```

逆に、ブラウザのタブを開いたままローカル版を使おうとしても同じことが起きます。
使わない方は必ず切断してください。



### スキャンしてもモータが見つからない (RX が 0 のまま)

「CAN コンソール」タブで TX 行だけが並び RX 行が出ない場合、フレームは正しく送出できていて
モータ側から返答が無い状態です。以下を順に確認してください。

#### 1. まずアダプタの DIP スイッチ (2 個) を確認する

マニュアル記載の正しい設定は **1 番 OFF / 2 番 ON** です。

| スイッチ | 設定 | 意味 |
|---|---|---|
| **1** | **OFF** | ON にすると Boot モードに入り、**ホストと一切通信できなくなります** |
| **2** | **ON** | 120Ω 終端抵抗がモジュール側ポートに接続され、正常に通信できます |

> 原文: "When DIP switch 1 is in the ON position, the module enters Boot mode and cannot
> establish a connection with the host computer. When DIP switch 2 is in the ON position,
> a 120Ω terminal resistor is connected to the module port, allowing normal communication
> with the host computer."

DIP 1 が ON のとき、CH340 (USB-シリアル変換チップ) は MCU の手前にあるため
**ポートとしては正常に見えるのに、モジュールからは 1 バイトも返ってこない**という
症状になります。「ポートは見えているのに RX が 0」の場合はまずここを疑ってください。

#### 2. それでも直らない場合

1. **モータの電源** — ロジックだけ USB から給電されていても、CAN トランシーバはモータ側電源が
   入っていないと応答しません。指定電圧が投入されているか確認します。
2. **CAN H / CAN L の結線** — 逆接続だと無応答になります。
3. **モータ側 CAN ボーレート** — 既定 1Mbps。過去に通信タイプ 23 で変更していると通信できません。
4. **CAN_ID** — 工場出荷時は **1** (0x200A CAN_ID の初期値)。ただし個体差に備えスキャン範囲は
   **0〜127** に広げてください。
5. **プロトコル設定** — 通信タイプ 25 で CANopen / MIT に切り替えてあると私有プロトコルでは応答しません。

#### アダプタ自体の生死を切り分ける

`docs/adapter-check.md` の手順で、シリアル速度 9 種 × コマンド 11 種を総当たりします。
**どれを送っても 1 バイトも返らない場合は、モジュールの MCU が動いていません**
(DIP 1 が ON / モジュール故障 / そもそも RobStride USB-CAN ではなく素の USB-TTL 変換基板)。

### macOS: CH34x 公式ドライバへの入れ替えが必要

**macOS 標準の CH340 ドライバでは通信できません。** ポートが `/dev/cu.usbserial-*`
として見えている場合は標準ドライバです (`AppleUSBCHCOM`)。ポート自体は正常に
見えるのにモータが一切応答しない、という症状になります。

1. **公式ドライバを入手する**
   <https://github.com/WCHSoftGroup/ch34xser_macos>

2. **インストールする**
   `CH34xVCPDriver.dmg` を開き、`CH34xVCPDriver.app` を `アプリケーション` へ
   ドラッグしてから、アプリを起動して **Install** を押します。

3. **機能拡張を許可する**
   `システム設定` → `一般` → `ログイン項目と機能拡張` → `ドライバ機能拡張` を開き、
   **CH34xVCPDriver** を有効にします。
   (macOS のバージョンによっては `プライバシーとセキュリティ` に
   「"CH34xVCPDriver" の機能拡張がブロックされました」と出るので **許可** を押します)

4. **アダプタを挿し直す** ← 忘れがち

   ドライバを入れたときにアダプタが挿さったままだと、デバイスの再マッチングが
   起きず標準ドライバが掴んだままになります。**必ず抜き挿ししてください。**

成功するとポート名が `/dev/cu.wchusbserial*` に変わります。

```bash
ls /dev/cu.wchusbserial*                      # ポート名で判別
ioreg -p IOService -l -w0 | grep -i CHCOM     # 標準ドライバが残っていないか
systemextensionsctl list | grep -i wch        # 有効化されているか
```

シリアル速度はマニュアルどおり **921600 bps** で通信できます。
判定根拠と詳しい切り分けは [docs/adapter-check.md](docs/adapter-check.md) を参照してください。

### シリアルポートが見つからない
CH340 のドライバが必要です。ポート一覧で `(CH340)` と表示されていれば認識できています。

### `address already in use`
`PORT=9000 ./run.sh` のように別ポートを指定してください。

## 構成

```
backend/
  protocol.py   フレームの組立/解析、拡張 ID、スケーリング、フィードバック復号
  models.py     機種別プロファイル (P/V/T/KP/KD レンジ)  ← 唯一の情報源
  params.py     パラメータ表と値のコーデック            ← 唯一の情報源
  transport.py  シリアル送受信、受信スレッド、応答待ち
  motor.py      モータ操作の高水準 API
  server.py     FastAPI (REST + WebSocket)
web/            ローカル版 UI (ビルド不要)
webserial/      Web 版 (静的・rs.fabo.io へデプロイ)
  protocol.js   protocol.py の移植
  robstride.js  Web Serial トランスポート + クライアント
  tables.js     backend から生成 (直接編集しないこと)
tools/          診断ツール・仮想モータ・テーブル生成
docs/           プロトコル要約とアダプタ切り分け手順
tests/          Python テスト
```

## テスト

```bash
./.venv/bin/python -m pytest tests -q   # Python 50 件
node --test webserial/*.test.js         # JavaScript 21 件
```

両者はマニュアル記載の同じ実フレームを基準にしており、片方だけ壊れれば CI で検出できます。
